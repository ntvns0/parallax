# Schema fixtures

One saved Parallax document per schema version. `core/schema-fixtures.test.ts`
opens every one and checks it migrates to the current build's geometry, and
`kernel/golden-parts.test.ts` rebuilds v4 onwards through OpenCascade against a
hand-computed volume.

From v4 on, every fixture is the same part: a 40 × 30 × 6 plate, a 20 × 12 × 4
pocket cut from a sketch on its top face, and an R2 fillet on one concave
corner of the pocket. v1–v3 hold only the plate, because a v1 extrusion has no
`operation` and the pocket's cut cannot be expressed.

## Where they came from

`schema-v8.parallax.json` was generated by the v8 build from feature factories
and the real anchor derivations. v9 is v8 with its version raised by hand,
since nothing in the plate uses what v9 added. The pre-release history was
squashed, so no older build survives to save the others. v1–v7 were produced
from v8 by undoing each migration step that `core/document-migration.ts`
documents:

| Version | Differs from the next version by |
| --- | --- |
| v8 | Revolves cannot name a sketch line as their axis, and sketches have no point-on-curve, point-to-line distance or symmetric constraints. The plate uses none of these, so v8 and v9 differ only in their version number. |
| v7 | No parameter table and no formulas |
| v6 | No face anchor on the face-attached sketch |
| v5 | No anchors on fillet edges |
| v4 | Face-attached cut stored as a positive distance |
| v3 | Same shape as v4 (no surviving record of what changed) |
| v2 | No solver anchor on sketches |
| v1 | No display units, no extrude `operation`, plate only |

## Bumping the schema

1. Raise `CURRENT_SCHEMA_VERSION` in `core/model.ts`.
2. Add the new number to `MIGRATABLE_SCHEMA_VERSIONS` in
   `core/document-migration.ts`, plus a migration step if the old shape needs
   more than defaults.
3. Save the pocketed plate from the new build as
   `schema-v{N}.parallax.json`. Use the app's project export, or copy the
   previous fixture and apply the change by hand. Keep the feature ids so the
   tests can find the features.
4. Never edit an older fixture to make a test pass. An older fixture stands for
   files that people already have.
